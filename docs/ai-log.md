# AI 개발 기록

M/L 작업마다 한 줄씩 남긴다. S는 기록하지 않는다 (기록 부담을 줄여 끊기지 않게). L은 쪼갠 계획마다가 아니라 기능 전체를 한 줄로 쓴다.
"이번 작업 ai-log에 기록해줘"라고 요청하면 Claude가 아래 규칙대로 채운다. timing.log에 기록이 없는 기간의 시간이나 크기처럼 알 수 없는 값은 추정하지 않고 묻는다.

- **Claude 작업 시간:** `.claude/hooks/timing.log`에서 작업 기간의 턴마다 `start` → 다음 `start` 전 마지막 `stop` 구간을 더한 값. 사용자가 답을 늦게 확인한 시간은 빠진다
- **총 경과 시간:** 작업 기간 첫 `start` ~ 마지막 커밋. 확인·결정에 쓴 시간까지 포함
- **크기:** M / L. 기준은 위험도이며 `docs/workflow.md`의 "작업 크기" 참고
- **AI 수정 반복 횟수:** 결과가 마음에 들지 않아 다시 고치라고 요청한 횟수. 훅이 자동으로 고치게 한 것은 세지 않는다
- **훅이 잡은 오류:** 해당 작업 기간의 `.claude/hooks/caught.log` 줄 수. 메모에 종류별(compile, test)로 나눠 적는다
- **리뷰 지적:** `/review-change`에서 고친 지적 수
- **체계:** 기준선(체계 없이 채팅으로) / 체계(명세→계획→훅→리뷰)

1단계가 끝나면 평균 Claude 작업 시간·총 경과 시간, 수정 반복 횟수, 훅이 잡은 오류 수를 아래 "정리"에 요약한다.
