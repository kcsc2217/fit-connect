# 변경분 리뷰 (5단계)

인자: 없음(커밋 안 된 변경 + 현재 브랜치의 main 대비 커밋) 또는 브랜치·커밋 범위.

M/L 작업의 필수 단계다. S 작업은 사용자가 요청할 때만 한다.

## 절차

1. 리뷰 대상을 정한다.
   - 인자 없음: `git diff main...HEAD`와 `git diff HEAD`(커밋 안 된 변경)를 합친 범위
   - 인자 있음: 해당 범위
2. `reviewer` 에이전트(`.claude/agents/reviewer.md`)에게 리뷰를 맡긴다. 프롬프트에 대상 범위, 관련 계획 파일(`docs/plans/`), 명세 파일을 알려준다.
3. 에이전트 결과를 그대로 옮기지 말고, 각 지적을 코드에서 직접 확인해 맞는 것만 남긴다.
4. 사용자에게 지적을 심각도 순으로 보여주고, 고칠 항목을 묻는다. 묻기 전에 고치지 않는다.
5. 고친 지적 수를 세어 두었다가 `docs/ai-log.md`의 "리뷰 지적" 칸에 쓴다.
