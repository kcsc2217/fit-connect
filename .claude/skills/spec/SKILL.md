# 기능 명세 정리 (1단계)

인자: 기능 이름 또는 요구사항 ID (예: `오프라인 동기화`, `FR-20~25`).

## 절차

0. 크기가 정해지지 않았으면 `docs/workflow.md` 기준으로 S/M/L을 제안하고 확정받는다. **S면 명세를 만들지 않고** 채팅 계획으로 넘어간다.
1. 원본을 읽는다.
   - `docs/prd.md` (요구사항 ID, 우선순위, 비기능 요구사항)
   - `docs/trainer-ssaem-spec.md` (기능 명세 원본, 있으면)
   - 관련 `docs/decisions/` ADR
2. 해당 기능에 속하는 요구사항 ID를 모두 찾는다. 다른 기능과 겹치는 부분은 "경계"에 적는다.
3. 원본에 없거나 모호한 내용은 **추측해서 채우지 않는다.** "열린 질문"에 적고 사용자에게 묻는다.
4. 아래 양식으로 `docs/specs/<기능-kebab-case>.md`를 만든다.
5. 열린 질문을 사용자에게 보여주고, 답을 받아 반영한 뒤 끝낸다. 계획·구현은 하지 않는다.

## 양식

```markdown
# <기능 이름>

- 요구사항: FR-xx, FR-yy (PRD 우선순위 P0)
- 상태: 초안 | 확정

## 목적
사용자가 얻는 것 한두 문장.

## 범위
- 포함:
- 제외 (다른 단계·기능):

## 동작
정상 흐름을 순서대로. 입력 → 처리 → 결과.

## 규칙과 제약
검증 규칙, 제한값(하루 N회 등), 정합성 요구(중복 0건 등), 비기능 요구.

## 예외 상황
| 상황 | 기대 동작 (응답 코드·에러 코드) |
| --- | --- |

## 데이터

| 메서드 | 경로 | 설명 |
| --- | --- | --- |

## 경계
다른 모듈과 주고받는 것 (ID 참조, 이벤트).

## 열린 질문
```
